# 어디에 쓰나 — 파일 위치와 분류

글 하나 = **파일 하나**다. 에디터로 마크다운을 쓰고 git 에 커밋하면 그게 발행이다.

```
src/posts/
└── <카테고리>/
    ├── <slug>.md
    └── images/
        └── <이미지 파일>
```

> `src/posts/` 가 비어 있는 것은 정상이다. 글 파일은 저장소 밖에서 관리된다.

---

## 1. 파일명 규칙

| 항목 | 규칙 |
| :--- | :--- |
| 파일명 | `<slug>.md` |
| slug 유일성 | **전역 유일**해야 한다. URL 이 `/posts/<slug>` 라 카테고리를 타지 않는다 |
| 공백 | **금지.** 하이픈을 쓴다 |
| 한글 | 허용된다 (카테고리·slug 둘 다) |
| 날짜 | **파일명에 넣지 않는다.** 날짜는 frontmatter 가 단일 출처다 |

slug 충돌 확인:

```bash
ls src/posts/*/<slug>.md
```

---

## 2. 분류 축은 둘이다

| 축 | 결정 방식 |
| :--- | :--- |
| **카테고리** | 글이 놓인 **폴더** |
| **하위 그룹** | 글의 **태그** (폴더 아님) |

### 카테고리 — 폴더로 정한다

`src/posts/<카테고리>/` 의 폴더명이 곧 카테고리다. 등록 절차는 없고, 폴더를 만들면 사이드바와 홈에 자동으로 나타난다.

```bash
ls src/posts/          # 기존 카테고리 확인
```

### 새 폴더를 함부로 만들지 마라

**기존 카테고리에 들어갈 수 있으면 새로 만들지 않는다.** 카테고리가 늘어날수록 탐색 축으로서의 기능이 무너진다 — 글 하나짜리 카테고리가 여럿 생기면 사이드바만 길어지고 아무것도 찾기 쉬워지지 않는다.

폴더명은 **공백 대신 하이픈**(`개념-정리`). 한글은 허용된다. 화면에는 하이픈이 공백으로 바뀌어 보인다.

---

## 2. 하위 그룹 — 태그로 자동 분류된다

카테고리 하나에 글이 쌓이면 그 안이 다시 주제별로 나뉜다. 이건 **폴더가 아니라 태그로** 결정된다.

`src/lib/subcategory-rules.js` 에 카테고리별 규칙 배열이 있고, 글의 `tags` 를 **위에서부터** 대조해 **첫 매치**로 분류된다.

### 글을 쓸 때 할 일

1. 해당 카테고리의 기존 규칙을 확인한다
2. **기존 태그를 재활용**해서 원하는 그룹에 들어가게 한다 — 이게 가장 쉬운 길이다
3. 어떤 규칙에도 안 걸리면 "미분류"로 떨어진다. 의도한 것이면 그대로 둔다

```bash
node scripts/build-posts-index.mjs
```

실행하면 `src/lib/posts-meta.json` 이 다시 만들어진다. 그 안의 `subcategory` 필드로 어디에 들어갔는지 확인한다. 이 JSON 은 **생성물이므로 직접 고치지 않는다.**

### 새 규칙을 추가할 때 — 순서가 곧 우선순위다

**더 구체적인 규칙이 앞에 와야 한다.** 첫 매치로 끝나기 때문이다.

예를 들어 어떤 글이 `[kubernetes, argo-rollouts, canary]` 태그를 가졌다면, `deployment` 규칙이 `kubernetes` 규칙보다 앞에 있어야 "배포 전략" 그룹으로 간다. 순서가 반대면 그냥 쿠버네티스 글이 된다.

**규칙을 추가하거나 순서를 바꾸면 기존 글이 조용히 다른 그룹으로 이동할 수 있다.** 에러가 나지 않으니 반드시 전수 확인한다.

### 왜 폴더가 아니라 태그인가

글 하나가 여러 주제에 걸치는 일이 흔하기 때문이다. 폴더는 하나만 선택할 수 있지만 태그는 여러 개를 붙일 수 있다. 그리고 규칙 파일 한 곳만 고치면 분류 체계 전체를 바꿀 수 있어서, 파일을 물리적으로 옮기는 것보다 훨씬 싸다.

작은 카테고리에는 하위 그룹을 억지로 만들지 않는다. 규칙을 비워두면 평평하게 나열된다.

---

## 3. 태그

`tags` 는 두 가지 일을 동시에 한다.

1. 태그 페이지(`/tags/<태그>`)의 필터
2. 위의 하위 그룹 자동 분류 입력

그래서 **태그 표기를 일관되게** 유지하는 게 중요하다. `Next.js` 와 `nextJs` 를 섞어 쓰면 태그 페이지가 둘로 갈리고 하위 분류도 어긋난다. 새 태그를 만들기 전에 기존 태그를 먼저 본다.
